## 另:「合进主线但不露出」不是零影响

即使设置页不露出开关,合进主线后:App 启动就无条件跑同步迁移(建表、加列、装触发器);启动时把 user id 写进同步状态;触发器让每次保存多记一笔账(单次保存 p50 多出约 0.1 ms)。

## 领导者裁定(AMEND-2)

不按「把 B1 的赋值补上」修,换一个让这一类 bug 结构上不可能的形状:

1. **同步从没开过 → 零影响**:零迁移、零触发器、零后台任务、零写库。第一次打开开关时才建表、才启动。
2. **归属改成无状态**:只有写笔记的那个进程,在自己的写事务里给行盖上当前 user id;同步层不再持有「当前用户」,不再有哨兵值与重试。
3. B1、M-1 随之消失;M-2 按新形状重写迁移后复审;L-1 进候补。
