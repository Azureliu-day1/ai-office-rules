# 派工简报模板

简报是领导者设计好的**完整施工路线**,不是一个目标。小兵按它做,不重新设计。
一批并行的活共用的规矩写进一份 `COMMON.md`,每份简报只写这一组特有的东西。

两份都要落在**持久目录**(项目 `docs/` 或一个专门的审计目录),不能只放在 agent 上下文里,也不能放在会被重启清空的临时目录。

---

## A. 单份简报

```text
推理档 <high> · 预计 <90> 分钟 · 退出条件:<一句话,可验证>。效率为主,预计只是预计,不是硬限。
角色说明:<若要覆盖角色文件里的某一段(例如换模型),写在这里;否则删掉这行>
先读:<基调文件路径>(基调与文件归属)、<COMMON.md 路径>(规矩、跑法、门)、<现状事实 / scout 报告路径>。

【worktree】<绝对路径或 ~/… 路径>(分支 <名>,基线 <commit>)。所有命令用绝对路径。
【文件】只许改:<文件清单>。只读:<文件清单>。⛔ 不碰:<别组在改的文件>;要动的结论写进报告由领导者安排。
【事实】<已知的数字与出处:谁在什么环境下测的、测到什么>。
【做】(按顺序;每条先证红再修,各自 commit)
  ① <条目:要达成的行为 + 判据>
  ② <条目>
  ③ <条目>
【接口 / 契约】<签名定死的接口;或「按 CONTRACT-x.md + AMEND-1.md,冲突处以 AMEND 为准」>
【门】(报告里逐条贴证据)
  ① 干净重建零 warning(贴计数)
  ② 自检 / 测试零失败,且通过数不少于基线(贴计数与最后 5 行;基线就红的,在基线上复跑一次证明)
  ③ 每条改动:先证红(贴未改代码上的失败原文)→ commit「自检:X 证红」→ 修 → commit「X」
  ④ <本组特有:截图前后对比 / 评测逐格不退 / 定向变异 N/N 证红 …>
【红线】<不开麦、不碰剪贴板、不合成按键、不装机、不 push、不 merge、不用 git stash …>
【回报即停】<缺接口;行为互相矛盾;要碰没点名的文件;撞上并发 / 取消 / 乱序;明显偏离预计>
【报告】写到 <持久目录>/<组名>-report.md;最终回复三行(做了什么 / 卡在哪 / 下一步)+ commit 表 + 每道门的证据 + UNKNOWN 清单 + 实际用时。
```

### 写简报的检查单

- [ ] 第一行有推理档、预计、退出条件(`hooks/check-brief.sh` 会拦)。
- [ ] 文件清单是**封闭**的:只许改这些;别组在改的点名列出。
- [ ] 每条「做」都有可验证的判据,不是「优化一下」。
- [ ] 跨组接口签名已经定死,并写进了两边的简报。
- [ ] 跑项目二进制的**唯一写法**已给出(见 `isolation-rules.md`),不留给小兵自己拼环境变量。
- [ ] 「回报即停」的条件写全了:小兵知道什么时候该停下而不是硬做。
- [ ] 证据落在持久目录,不在临时目录。

## B. 共用规矩(COMMON.md)

```text
# <线名> · 各组共用规矩(领导者 <日期>)

【规矩】先读 <operating-model 路径> 的事故条款。用户在用电脑时:⛔ 不开麦、不跑会碰真剪贴板 / 合成按键的验证、不装机、不 push、不 merge、不碰 <别的线在改的文件>。
只改简报点名的文件;撞上并发 / 取消 / 契约缺口 → 停下写进报告;⛔ 不用 git stash(多个 worktree 共用一个 stash 栈)。

【worktree】<路径模板>-gN,分支 <线名>-gN,基线 <commit>。

【跑二进制的唯一写法】
  env -i HOME=$(mktemp -d) PATH="$PATH" DEVELOPER_DIR=<开发者目录> \
      <APP>_STORE=memory <APP>_SELFTEST=1 <二进制路径> </dev/null > <log> 2>&1

【门】<同 A 的门,全组共用的部分>
【证据落地】<持久目录>/<日期>-<线名>/gN/
【报告格式】三行 + commit 表 + 门证据 + UNKNOWN 清单 + 实际用时。报告不进仓库。

【补充 <时间>(领导者裁决)】<施工中出现的共性问题的统一裁定,按时间追加,不改上面的正文>
```

「补充」一节很重要:施工中发现的共性问题(例如某类截图永远不会逐字节一致,因为带墙钟时间),领导者裁定一次、追加一段,所有组照同一个裁定做。

## C. 部署简报的额外骨架

部署简报在 A 的基础上,把【做】换成**一步一停看结果**的顺序:

```text
【为什么现在能上】<功能默认关 / 客户端未出货 / 有服务端停用开关 / 已过独立审核(阻断 0)>
【顺序,一步一停】
0 回滚点:记下线上当前版本与对应提交;备份将被替换的东西到 <持久目录>;本地 tag(不 push)。
1 部署前手动跑哨兵(部署脚本的前门不跑的那些),必须 0 失败。
2 查线上环境版本(只读),记进日志。
3 迁移按序:dry-run → 看输出 → commit;每份之后重导基线并查漂移。⛔ 顺序依赖写明。
4 迁移后核权限:新对象对匿名 / 普通角色无任何权限;新函数无公开执行权。只读查询,结果贴证据。
5 线上探针先红(部署前)。
6 部署。
7 线上探针再绿:功能、限频、停用开关(用完立刻关回并核对快照)、并发、客户端断开。
8 自清:探针造的账号与数据清掉(审计行不删);配置快照回到探针前。
9 部署日志追加(迁移 / 部署 / 探针各一行,含回滚点),commit。
【红线】只动本批对象;密钥值不进日志 / 报告 / 回复;真实用户的身份信息不进任何载荷;不删数据(探针自己造的除外)。
【回报即停】dry-run 与预期不符;探针红且 15 分钟内定不了是脚本还是服务;线上出现错误告警;需要改已审过的逻辑才能绿 —— 回滚到 0 的回滚点再回报。
```
