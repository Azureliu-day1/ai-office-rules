# 隔离规则:测试和自检进程不许碰用户的真实世界

AI agent 会在用户正在用的那台机器上跑测试、自检、截图、探针。这份规则每一条都来自一次真实事故(见 `incident-lessons.md`):agent 以为自己「隔离」了,系统却把求助弹到了用户脸上,或者把测试数据写进了用户的真库。

**总原则:隔离不能靠调用方记得给环境变量。** 同一类事故反复发生,每次都是某个调用方漏了一个变量。所以:

> **测试缝按进程身份自动生效;环境变量只能收紧,不能放松;每多一种真数据,环境门就多一问。**

---

## 一、跑项目二进制的唯一写法

项目里任何二进制(自检、评测、验证脚本、探针)一律:

```bash
env -i HOME="$(mktemp -d)" PATH="$PATH" \
    DEVELOPER_DIR=<你的开发者目录> \
    <APP>_STORE=memory <APP>_SELFTEST=1 \
    <二进制> </dev/null > <log> 2> <err> | cat
```

逐项的「为什么」:

| 项 | 为什么 |
|---|---|
| `HOME=$(mktemp -d)` | 刚构建的二进制签名和已安装的不同,读钥匙串会弹系统授权框;授权框挂在用户屏幕上,还会全局开着安全输入模式,让别的东西假红 |
| `</dev/null` | 防止进程等终端输入挂住 |
| 输出走管道 / 文件 | 防止交互式提示 |
| `env -i` + 显式 `PATH`、`DEVELOPER_DIR` | 干净环境;但隔离环境里某些系统工具的 shim 找不到开发者目录时,会在用户屏幕上弹「要不要安装开发者工具」 |
| `<APP>_STORE=memory` | 真库不许被写,哪怕插一条再删掉 |
| `<APP>_SELFTEST=1` | 所有测试缝认的是**同一个键**;验证脚本给的键和测试缝认的键不一致,是一整类事故的根因 |

把这条写法**原样**放进 `COMMON.md`,不留给小兵自己拼。

⚠️ **`HOME` 隔离挡不住一切**:有些平台的「应用支持目录」「偏好域」不认 `HOME`,仍然指向真目录。所以才需要下面的第二节。

## 二、测试缝由进程身份决定

程序启动时判断「我是不是自检进程」(例如:进程名 / bundle id 带 `.selftest` 后缀,或自检入口被调用),一旦是:

- 所有**持久化**(数据库、账本、历史、导出文件、诊断日志)自动切到进程私有的临时目录或内存;
- 所有**偏好 / 设置域**切到私有域;
- 所有**窗口**走无头路径(不 orderFront、不交给窗口服务器);
- 所有**网络监听**(socket、本地服务)不开或开在私有端口;
- **截图模式**也算自检:强制内存库、强制私有设置域,不给就拒跑。

**自检进程发现自己落在真目录里 → 启动即红,不再往下跑。** 例如:诊断目录在真的应用支持目录下、进程用的是真 bundle id、偏好域是真的那一份。

**用真身份跑自检是事故**:进程的默认偏好域就是用户真实的设置域,框架会顺手往里写键。需要「系统扩展 / 插件形态」这类必须以特定身份运行的自检,只在**改了身份的副本**上跑。

## 三、环境门:跑前跑后各问一遍

每道合并门之前,跑一个环境门脚本,逐问回答;任何一问红就不跑:

1. 诊断 / 日志目录不在真应用支持目录里?
2. 剪贴板:自检不读写真剪贴板?(跑前跑后内容指纹不变)
3. 设置域:自检用的是私有域?(真偏好文件跑前跑后指纹 + mtime 不变)
4. 用户数据目录(个人数据、导出、缓存)被指到进程私有目录?
5. 数据库:内存库或私有库?
6. 使用账本 / 统计:私有库?
7. 进程默认偏好域:不是真身份的那一份?
8. <你的产品每多一种真数据,就在这里加一问>

漏一问,就是下一次事故。

## 四、用户在场时不做的事

判断「用户在场」:键鼠空闲时间 < 10 分钟(macOS 上可读 `HIDIdleTime`)。在场时:

- ⛔ **不开麦克风**。会开真麦的自检,会把用户的蓝牙耳机切进通话模式(音质骤降、正在听的东西被打断)。另外:默认输入是蓝牙设备时,即使用户不在场也不跑。
- ⛔ **不碰剪贴板**。写真剪贴板「再还回去」的自检,会撞上用户刚复制的东西。
- ⛔ **不合成按键 / 点击到别的 App**。
- ⛔ **不安装 / 覆盖用户正在用的 App**(进程会被删掉重写)。
- ⛔ **不弹出任何面板**:模拟器面板、浏览器窗口、系统对话框。测试与截图全程无头(命令行工具驱动模拟器,不调用会在用户屏幕上开面板的工具)。

会碰这些的验证,等用户离开 ≥ 10 分钟再跑;合并门在用户在场时只用无头自检 + 零 warning。

## 五、别人的 App

自动化必须碰别人的 App(浏览器、编辑器)时:

- **开自己的窗口**,不往用户现有窗口里塞标签;
- **只关自己的标签**,不按「当前标签是我的」去关整个窗口;
- 开始前**盘点**窗口,结束后**核对**,不一致就大声记下并恢复;
- 不能盘点的对象不碰。

## 六、无头浏览器与隔离环境里的系统求助

- 无头 Chrome 类浏览器一律带 `--use-mock-keychain --password-store=basic`:只换临时 `HOME` 不够,它会在用户屏幕上弹一串「找不到钥匙串」。
- 任何截图 / 探针 harness 启动前后各查一次有没有弹出授权 / 安装 / 钥匙串类的系统进程(例如 `pgrep -fl 'SecurityAgent|Keychain'`)。
- agentic CLI 的探针用**空目录**当工作目录。

## 七、数据出机

- **个人语料出机前必须过本机闸**:只放行已知公开、且不在敏感话题表里的条目;未知项默认不外发;关系数据(组合、共现)整体不外发。
- ⛔ 任何「让模型先看一眼再决定发不发」的步骤都不算闸 —— 那一眼已经外发了。
- **通道要裸**:固定提示词 + 已过闸正文 + schema。会自带用户配置、记忆、规则、工具的 agentic CLI,会把这些一起发出去;有的还有服务端工具(联网搜索等)客户端关不掉。上线前用合成数据抓一次完整出站报文;出站审计里服务端工具调用一律标红。

## 八、公开仓推送

- 推送前的个人信息 / 密钥扫描必须 **fail-closed**:命中就整条链停下,不 add、不 commit、不 push。
- ⛔ 不要写成 `grep … ; git add … && git commit … ; git push` —— 分号让命中不挡后续。用 `scan && git add … && git commit … && git push`,或脚本里 `set -e`。
- 小兵的产物(夹具、截图、日志)落仓前先当「含个人信息」处理,不是先当干净。
- 扫描器本身要**逐条模式证红**:一个模式静默失效(例如正则里的 `|` 被当成分隔符截断),整组看起来照样「部分绿」。

## 九、读账本 / 统计前先扣自检

如果历史上自检曾经写进过真账本,报告任何读数前先扣掉自检来源(例如 `client like 'test.%'`),并写明扣了多少。否则账本上看起来常用的功能可能真实一次都没被用过,拿它做产品判断的人会被骗。
