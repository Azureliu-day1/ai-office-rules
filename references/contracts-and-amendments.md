# 契约 → 对抗 → AMEND 修订

跨 agent 的接口、数据契约、隐私边界,都先写成**契约文件**,再派施工。契约不是一次写对的:它会被对抗审核、被施工中撞到的缺口、被独立审核的阻断项反复修订。修订不改原文,而是追加编号的 **AMEND** 文件。

## 流程

```
领导者写 CONTRACT-<名>.md (v0.1)
        │
        ├──► 派施工(builder 按 v0.1 开工,只做不受争议影响的部分)
        │
        └──► 并行:对抗审核(另一家模型)挑契约
                  │
                  ▼
        领导者写 AMEND-1-<名>.md (v0.1 → v0.2)
        在 CONTRACT 顶部加一行:「已被 AMEND-1 修订,冲突处以 AMEND-1 为准」
                  │
                  ▼
        builder 按 CONTRACT + AMEND-1 施工;撞到没覆盖的缺口 → 回报,不悄悄重设计
                  │
                  ▼
        独立审核 → 阻断项 → 领导者裁定 → AMEND-2 … → 放行
```

## 契约文件怎么写

1. **共同红线放最前**:默认开还是关、用户在什么时候知道数据会发到哪、关掉的语义、哪些东西永远不发。
2. **每件功能一节**:触发条件、请求 / 响应形状、服务端守什么、客户端守什么、计量、远程停用开关。
3. **签名定死**:端点、字段名、错误码(带 `reason`)。两边的 builder 都照这一份。
4. **写明不做什么**:「⛔ 不同步 X」「⛔ 不发 Y」。没写「不」的地方,builder 会按自己的理解补。
5. 版本号写在标题里(v0.1),修订后的有效版本写在顶部那行里(v0.2 = v0.1 + AMEND-1)。

## AMEND 文件怎么写

- 标题:`AMEND-N · <契约名> v0.x → v0.y(<领导者>,<日期>;来源:<对抗审核报告 / 独立审核报告>,结论「<修改 / 不放行>」)`。
- 第一段:「与 CONTRACT 冲突处**以本文件为准**」+ 范围有没有缩。
- 条目编号(A1、A2… / B1、B2…),**每条是一个可验证的行为**,不是一段讨论。
- 结尾写「验收自检至少覆盖」清单:每条关键修订对应一条自检。
- 结尾重申:每做完一条就 commit;撞到本文件没覆盖的并发 / 契约缺口,回报。

## 对抗审核在契约上最常改的几类

这些是真实项目里一轮对抗后被改掉的形状,写契约时可以先自查:

| 契约 v0.1 的写法 | 对抗后改成 | 为什么 |
|---|---|---|
| 同步冲突按客户端时间戳「新者赢」 | 服务端给每次写入盖单调版本号(rev),客户端带 `base_rev`,服务端比版本号 | 客户端时钟不可信;离线的旧写会盖掉新删除 |
| 删除墓碑保留 30 天 | 墓碑不过期(另计上限) | 离线超过 30 天的设备回来会把删掉的东西复活 |
| 「清空云端」只删行 | 加一个数据代次 epoch:清空 = 删行 + epoch+1;旧代次的请求一律 409,客户端自动关同步 | 别的设备和旧队列会把清掉的数据传回来 |
| 客户端状态不分账号 | 游标 / 队列 / 代次按账号分开;登出或换账号 → 同步关、队列清 | 上一个账号的数据推给下一个账号 |
| 拉回来的数据照常「学习」 | 拉回的不算本地修改:不加计数、不标脏 | 否则回传、循环 |
| 载荷带来源、客户端时间、设备型号 | 载荷最小化:只留合并必需的字段;设备 id = 每次安装随机生成 | 少发一个字段就少一类泄漏 |
| 自动触发云端请求 | 显式触发为主,自动触发是默认关的子开关 | 用户知道自己什么时候在发数据 |
| 回包到了就显示 | 请求绑定(会话 id + 代际);回包时核「会话、代际、焦点、开关」都没变,任一不符丢弃;只比内容不够(A→B→A) | 迟到回包会落在错误的上下文里 |
| 停用开关只在客户端 | 服务端也拦;每用户与全站上限在服务端计 | 旧版本客户端和被改过的客户端不听话 |
| 「关掉 = 立刻撤回」 | 关掉 = 停新请求 + 取消在途 + 迟到回包丢弃;文案不许说「撤回」 | 已经发出的收不回,文案不许说谎 |
| 「只有你能读」 | 如实写「服务端可读,不是端到端加密」 | 披露必须是实话 |
| 网络在输入 / 主交互路径上 | 网络全在关键路径之外;云端永不回包时关键路径延迟不变(配一条自检) | 云端失败不许拖慢本地 |

## 独立审核后的 AMEND

独立审核给出阻断项后,领导者裁定时常常不是「照着修」,而是**换一个更简单的形状**,让那一类 bug 结构上不可能再发生。例如(见 `examples/review-example.md`):

- 阻断:一个「归属未确认」的哨兵状态只在自检里被赋值,生产里恒为默认值。
- 裁定不是「把赋值补上」,而是 AMEND:① 功能从没打开过 → 零迁移、零触发器、零后台任务、零写库;② 归属改成无状态 —— 只有写数据的那个进程在自己的写事务里盖归属,不再有哨兵与重试。

## 跨 agent 接口的规矩

- 签名在派工前定死,写进**两份**简报。
- 统一连线由领导者在一个明确步骤里做(例如「在合并 X 之后,由领导者加那一行调用并跑自检;本线不写」),不让两个 agent 各接一半。
- 施工组在报告里标「行号漂移」即可,不自己去接另一半。
