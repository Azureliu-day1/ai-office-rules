# 角色与模型

## 一条原则

**这一步需要判断,还是只需要动手?**

- 需要判断(定方案、写契约、审成品、拆真难的 bug)→ 顶级模型,推理档 high(最多 xhigh)。
- 需要动手但要质量(按契约施工、侦察采集、写详细文案、写脚本)→ 强模型,推理档由领导者按任务估。
- 只产数据、不需要判断(批量生成 / 筛选 / 清洗 / 投票)→ 便宜快速的模型,低推理或关掉推理,大批量并行,产出再由流水线的门把关。

⛔ 不用小模型「省钱」做需要判断或施工质量的活。降的是推理档,而且只在不需要判断的地方降。
⛔ 最高推理档不是默认:只在特别必要时用(真难的 bug、要一次定对的决策),并在派工账里写明为什么。

## 角色

| 角色 | 做什么 | 不做什么 | 建议模型 / 档 |
|---|---|---|---|
| **总领导者**(主会话) | 定战略:基调、契约、原则;执行战略:派工、合并、装机、验收;当审核官 | 亲手写文案、写脚本、跑批量、出图 | 顶级模型,high |
| **路线领导者** `agents/lead.md` | 多条线并行时,每条线一个:按总领导者的简报定路线、写小兵简报、派工、合并本线、记账 | 写大段代码、跑批量 | 强模型或顶级模型,high(⛔ 不开最高档) |
| **builder** `agents/builder.md` | 按简报施工:铺字段、接线、改文案、实现已定方案;先证红再修、每条 commit | 重新设计、改简报没点名的文件、改断言让测试变绿 | 强模型,high |
| **scout** `agents/scout.md` | 探测、采集、测量:翻仓库、查符号表、抓日志、跑测试记数字、查文档 | 做设计判断、改项目文件 | 强模型,high(事实类也可更低) |
| **curator** `agents/curator.md` | 批量产数据:词表、样例、测试语料、分类标签 | 做功能、改源码、跑项目二进制 | 便宜快速模型,low |
| **独立审核者** | 只读审成品,自己做变异 | 读 builder 自证报告、边审边修 | 没参与施工的强模型或顶级模型 |
| **对抗审核者** | 另一家厂商的顶级模型:挑方案、挑契约、挑成品 | 当施工队 | 外部顶级模型,高推理 |

## 职责边界

- **scout 只交事实**:每条带出处(文件:行号 / 命令输出 / URL 原文)、环境(OS build / 设备 / SDK)、搜索范围、失败的命令、缺失的证据。证据互相矛盾、或查到的是模拟器而不是真机,**必须标 INFERENCE**。拿不到就写 UNKNOWN + 原因,不猜。
- **builder 撞上难题要回报**:并发、取消、乱序、线程隔离、契约缺口 —— 回报并等升级,不按「机械活」硬做,不悄悄重设计。
- **领导者对整个切片负责**:子 agent 做完不等于切片完成;多份审核意见不自动等于决策。
- 只跑一条已知命令的事不派 agent,领导者直接跑。

## 审核的独立性来自哪里

来自「**没参与施工**」,不来自厂商。外部模型额度用完时,用一个独立的、只读的、不读 builder 报告的、不同上下文的审核者顶上,这不是降档。外部模型的第二意见等额度回来再补。

## 批量数据活的出机通道

只产数据的批量活常常会把项目语料发给外部模型。两条硬规矩(来自真实事故,见 `incident-lessons.md`):

1. **筛选在本机、在任何云端调用之前**。「先让模型分类,再把私人的留本机」= 分类那一步已经外发了。闸是纯本机脚本;未知项默认不外发;关系数据(组合、共现)比单条更暴露,整体不外发。
2. **传输要「裸」**:固定提示词 + 已过闸的正文 + 输出 schema。agentic CLI 会把用户级配置、记忆、规则一起带进每次请求;有的还带**服务端工具**(联网搜索、代码执行),客户端开关关不掉。用 agentic CLI 当批量通道之前,先用合成数据抓一次**完整出站报文**核对,并在出站审计里把服务端工具调用标红。

## 派工账

基调文件里记每次派工:时间 / 活 / 模型与档(requested → 实际生效)/ 时长(预计 → 实际)/ 产出。缺的写 UNKNOWN。里程碑汇报的成本行从这里取数,不靠估。

## 自定义角色的两个坑

- 新建的角色文件通常要**下一次会话**才被加载。当场要用,就用现有角色 + 模型覆盖,并在简报里写明「角色说明覆盖角色文件里的某一段」。
- Agent 工具一般没有推理档参数,子 agent 的档位来自角色文件的配置。
