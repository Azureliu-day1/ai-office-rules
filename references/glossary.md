# 词汇表

本技能里反复出现的词,每条一两句 + 一个极短的例子。

| 词 | 意思 | 例子 |
|---|---|---|
| **基调(基调文件)** | 开工前写的一页纸:目标、做与不做、验收、里程碑、预算、红线。用户说「行」之后,它是唯一的工作清单。 | `docs/BASELINE-sync.md` 里写「不做:附件同步」,那附件同步就进候补,不做。 |
| **简报** | 领导者派给子 agent 的完整施工路线:做什么、改哪些文件、接口、顺序、门、回报即停、报告格式。第一行固定写推理档 / 预计 / 退出条件。 | `推理档 high · 预计 60 分钟 · 退出条件:测试全绿且变异 5/5 证红。` |
| **回报即停** | 简报里列出的情形:一旦遇到就停手写报告,不硬做、不自己改设计。 | 「要改简报没点名的文件」→ 停下回报,由领导者安排。 |
| **契约 / AMEND** | 契约:跨 agent 的接口与行为约定,派工前定死。AMEND:对契约的编号修订,冲突处以 AMEND 为准,原文不改。 | `CONTRACT-sync.md` v0.1 + `AMEND-1-sync.md` = 有效版本 v0.2。 |
| **worktree** | git 的「同一仓库多个工作目录」。每个 builder 一个,互不踩文件。 | `git worktree add ../app-sync-c -b sync-c` |
| **证红** | 先在**未改的代码**上跑新写的测试,确认它失败;再改代码让它变绿。没证过红的测试,不知道它能不能抓到问题。 | 写「换账号后队列为空」的测试 → 旧代码上跑出 ❌ → commit「自检:X 证红」→ 修 → commit「X」。 |
| **哨兵** | 一条守住某个结构事实的检查,常是 grep 式的:某个调用必须在、某个禁用写法必须不在。 | `grep -c 'applyRemote(' SyncClient.swift` 必须 == 1。 |
| **轻门** | 施工期每个 builder 自己要过的最小门:编译零 warning + 自己那一节的定向测试 + 一条冒烟。 | 不跑全量变异、不跑全部 UI 测试。 |
| **变异(变异测试)** | 故意把生产代码改坏(删一行、翻一个条件),看测试会不会红。不红 = 测试是摆设。 | 删掉 `clearQueue()` 那行 → 「换账号」测试应当变红。 |
| **恒真断言** | 无论代码对错都成立的断言,永远是绿的。 | `assert(x == a \|\| x.id == b)` 两边都真;`abs(p - p) < 0.01`。 |
| **夹具(fixture)** | 测试为了跑起来而预先搭好的数据、对象或接线。夹具可能替产品把线接好,于是测试绿了、产品没修好。 | 测试里手动给 `client.owner = "u1"`,而生产里从没人赋这个值。 |
| **自证报告** | builder 交上来的「我做了什么、门都过了」。独立审核者**不读**它,免得注意力被引到 builder 想让人看的地方。 | 审核者只拿 commit、验收 ID 和契约。 |
| **独立审核 / 对抗审核** | 独立:没参与施工的审核者,只读、不读自证。对抗:最好换一家厂商的模型,专门挑刺、找漏、给替代。 | 见 `adversarial-review.md`。 |
| **阻断项** | 会破坏验收、数据、隐私 / 权限、计费、发布条件的问题。只有它挡合并与交付。 | 「换账号后旧账号的数据被推给新账号」是阻断;按钮颜色不是。 |
| **回滚点** | 部署前记下、能一键回到的状态:线上当前版本 + 对应提交 + 备份 + 本地 tag。 | `git tag pre-deploy-2030-01-18` + 函数源码备份。 |
| **探针(先红后绿)** | 部署前后对线上跑的小脚本。部署前应当红(证明它能抓到缺失),部署后变绿。 | 新端点部署前返回 404 → 红;部署后 200 → 绿。 |
| **first demo** | 一个切片第一次给用户看的日子,不等切片全做完,让用户尽早纠方向。 | 同步做完一半就给一个能装的包,让用户在两台设备上试一次。 |
| **切片 / 里程碑** | 一个用户能当场演示的功能片段;里程碑按切片算,不按提交数算。 | 「在手机上改一条笔记,电脑上 10 秒内看到」。 |
| **验收即回归** | 每个切片的用户验收各落成一条自动化测试;以后每次合并和 review 都先把它们全跑一遍。 | 测试名 = 验收 ID,例如 `test_V1_syncWithin10s`。 |
| **INFERENCE** | 标记「这是推出来的,不是看到的」。推断必须和原文 / 实测分开标。 | 「用户多半不会点这个按钮(INFERENCE,依据:入口在第三层)」。 |
| **UNKNOWN** | 查过、便宜的办法查不出来。它不等于「没问题可以做」;关键假设 UNKNOWN 时不开大工。 | 「新系统版本上这个接口还在不在:UNKNOWN(没有该版本的设备)」。 |
| **REQUIRES_REVIEW / FORBIDDEN** | 红线两档。FORBIDDEN:不许碰。REQUIRES_REVIEW:改了要先单独过审再合(引擎核心、账务、权限、数据迁移、上传路径)。 | 改计费逻辑 → REQUIRES_REVIEW。 |
| **派工账** | 基调里记每次派工的配置与实际:模型与档、预计与实际时长、产出。汇报的成本数字从这里取。 | `10:05 · sync-c · 强模型 high → high · 120 → 95 分钟 · 6 commits`。 |
| **断点** | 额度或上下文快满时,写在基调里的「在跑什么、到哪了、恢复后第一步做什么」。 | 「sync-c 做到第 4 条,已 commit 到 `a1b2c3d4`;恢复后先看 git status」。 |
