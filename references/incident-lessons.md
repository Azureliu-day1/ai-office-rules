## 第二部分:审核反复抓到的 bug 形状

多批功能每批都跑对抗审核,每批都抓到自检和编译器看不见的真 bug。反复出现的是这几类,写代码和派审核前都拿来自查:

1. **接线缺失**:功能整体是死代码,而自检全绿(自检是合成喂数据,测不到接线层)。→ 每条新数据通路配一条「调用点」哨兵。
2. **断言恒真**:守着最危险那条底线的测试从没真正判断过(`X == A || X.field == B` 两边都真;`abs(p.y - p.y)`;拿自检自己写死的拷贝去比)。→ 每写一条断言问:「什么变异能让它红?」答不上来就是摆设。
3. **失败路径不对称**:主路径周全,失败路径丢了数据或撒了谎(失败时删掉原始数据不落历史;说「已保存」却没核实;空结果当成功)。→ 每条 return 前问:「用户的东西还在吗?界面说的是实话吗?」
4. **两条规矩互斥**:分段拼装的产物(提示词、配置、生成文件)里两句各自无条件下发、互相矛盾;每句单独 grep 都在,哨兵全绿。→ 把成品拼出来比,不只 grep 每一段在不在。
5. **验证计划覆盖不到第二个周期**:续费 / 续期 / 第 N 次才现形的 bug,会从「走一遍收银台」这种唯一的验证里全身而过(例:某支付平台续费事件顶层的周期末尾是**上一个已结束周期**,服务期在明细行里)。→ 凡有周期概念,专门构造第二次;问「哪种失败会等到我验完之后才发生?」
6. **平台的默认行为**:你没做的事,平台替你做了(例:Postgres 新函数默认对 PUBLIC 可执行,而 REST 层会自动把函数暴露成端点;`create or replace function` 改了参数个数是新建重载,旧签名还在,调用变成歧义)。→ 用平台能力时先问「它默认会替我做什么」。
7. **同步改异步开了一个交错窗口**:「读快照 → 生成 → 写回」改成后台生成后,中间可能插进别的写入,旧快照回来把新结果盖掉。→ 快照编号,落地前核有没有更新的一次。
8. **状态用单布尔**:「挂起」用一个布尔,别处的恢复会悄悄解除你的挂起。→ 挂起原因用集合 / 令牌。
9. **「进程在」≠「能接管」**;「重启自己」要等旧进程真退出再拉起。
10. **实时线程上的隔离断言**:在音频渲染这类实时回调里调用「假定在主线程」的 API 会直接崩,编译器一个字不说。→ 实时回调里只准无锁原子量。
11. **ARC / 引用计数**:局部变量最后一次使用后就可能被释放,从它取出的裸指针随之失效(release 优化后才出现)。→ 需要时显式延长生命周期。
12. **插错闭包编译是绿的**:声明式 UI 里把视图加进了一个永远不显示的弹窗闭包。→ 任何「把 X 挪到 Y」的改动,装上去看一眼 X 在不在。
13. **母语界面看不见的漏翻**:漏掉本地化的字符串在母语界面上完全正常。→ 装上去切成另一种语言逐页走。
14. **离开产品自己的读口去聚合原始表**:把「每次展示了几个」当成「次数」求和,指标错了一倍多。→ 先查列语义;能对上产品界面已有的数就对一次。

## 第三部分:哨兵 / 测试自身的坑

哨兵(grep 式的结构检查)和测试会以各种方式「假绿」。**共同点:没有先证红就当它成立。**

- 找「有没有」时没锚定行首:把那行注释掉照样命中。**证红要真删行,注释掉不算。**
- 只认一种写法:手写的小写、导出的大写加 schema 前缀,数少了一半。**哨兵要报出它数到了几个,并和真实数量对一次。**
- 裸标识符在白名单 / 常量表里顶包:删掉真正的调用照样绿。**只准 grep 调用点。**
- 阈值挑得比实际出现次数低(`>= 2` 而实际 7 处)。**能写 `== N` 就别写 `>= N`,先数一遍。**
- 子串陷阱:`var x` 被 `private var x` 包住,计数不变。
- 引用了在它后面才定义的变量,整条管道恒绿,`|| true` 把失败也吞了。
- 模式里带 `$0` 却用了双引号,被 shell 展开成脚本名。
- 守 shell 脚本的哨兵忘了过滤 `#` 注释。
- 分隔符和内容撞车(模式里自带 `|`):五条里三条红得漂亮,两条静默失效。**每条模式单独证红。**
- 覆盖率断言两条都读生产表 = 恒真。**要两条方向相反的断言**:遍历生产表 + 拿具名清单反查。
- 变异锚在一个裸符号名上,改到的是解释它的注释。**变异锚一整句代码。**
- 用 awk 切代码块做哨兵要设终点并跳注释,否则会匹配到后面的函数。
- 禁词哨兵会抓到自己人:把禁词表挪到它本来该在的规则表里,⛔ 不加豁免标记(豁免标记是后门)。
- 判据会过期,过期的判据比没有判据更坏:文档里的判据定期回去验。
- 「老账」必须每条有一句「哪一行坏了」;说不出就不是老账,是坏掉的哨兵。
- 验证与提交不串在同一条命令里:提交信息里的数字要先看见再抄。

## 第四部分:提进主干的五条(细节)

这五条在 `SKILL.md` 第 4–6 步各有一两行;这里是它们的来龙去脉。

1. **生产接线要有一条不经过夹具的断言。** 真实形状:修复写在一个属性的 `didSet` 里;测试夹具给这个属性赋了值,于是 `didSet` 触发、测试全绿;而生产入口从没给它赋过值,默认值不触发 `didSet` —— 修复在生产里从来没执行过。连续两轮自检全绿,是独立审核按生产接线端到端跑才发现的。判据:问「如果把测试里的注入 / 夹具拿掉,这条还能绿吗?」至少一条测试从生产入口进、零注入。
2. **测试读到真实系统状态会时红时绿。** 真实形状:① 屏幕锁着时系统占着安全输入,两节自检跟着红,解锁就绿;② 一条测试往共享设置里写了一个模式开关,泄漏给后面的测试;③ 有状态的哨兵去读模拟器的共享容器,被并发的另一个 agent 改掉,假红。判据:测试需要的系统状态一律在现场注入(传参、私有设置域、专用模拟器),不读机器上的真状态;一片红时先查这类环境因素再查代码。
3. **会话重启会杀掉所有在跑的子 agent。** 子 agent 活在主会话里:主会话重启、额度撞满、机器重启,在跑的全部中断,不交报告、留着未提交的改动。能救回来的只有三样:落在持久目录的简报、已经 commit 的条目、`git status` 里做到一半的改动。所以简报落盘、每条 commit 不是洁癖,是接手成本。
4. **多个 agent 共用临时目录会互相覆盖同名脚本。** 两个 agent 都往同一个临时目录写 `run.sh` / `probe.py`,后写的覆盖先写的,先写的那个跑的是别人的脚本,结果看起来「偶尔不对」。每个 agent 用 `mktemp -d` 拿自己的目录,脚本名也带组名。
5. **「开关不露出」≠「对用户零影响」;连续两轮审出新问题就改设计。** 真实形状:一个功能「合进主线但设置页不露出」,独立审核单问了一句「对用户是不是真的零影响」,发现 App 启动照样无条件跑迁移、写库、装触发器,每次保存都多一笔开销。同一处已经连着两轮审出新问题;领导者没有再补第三次,而是换了形状:功能没打开过就零迁移、零写库;归属改成无状态。之后这一类问题结构上不可能再出现(见 `examples/review-example.md` 的 AMEND-2)。
